## New Falsifiable Rule

For a new or changed activity handoff beneath a sticky header, record one
source-link/target-heading row with viewport, text mode, input, header bottom,
heading top and visual outcome. Activate the actual route with keyboard and
touch as relevant, at desktop/mobile normal text and a mobile200%root-text
stress setting. Check direct hash and return navigation where part of the task.
Success: destination heading and beginning of instructions are visible without
corrective scrolling; heading top is at least header bottom; no clipping or
horizontal overflow. Geometry alone does not replace visual inspection.

This operationalizes the existing accessibility review, not a universal zoom
certification or mandatory site-wide36-case matrix. Scope to touched routes;
existing action-specific broader QA still applies. Record N/A if no such
handoff/header exists. Do not create parent-facing explanation of the test.

Hypothesis: explicit route-arrival evidence catches this class of hidden-start
defect before release more reliably than generic text-fit/link checks alone.
Confidence: moderate; one repeated pattern across two guides, not a controlled
experiment. Next falsification: a reviewed changed route still hides its target
in the recorded setup. Reproduce font/browser/header conditions and revise the
test or implementation, rather than add generic prose. No new route was tested
today; the prospective rule's effectiveness remains unmeasured.
