# Dedicated Activity Guide Strategy

Date: 2026-09-06

Action: `KAL-STRAT-001`

State: independently review-clean; `PASS` with no P0-P3

## Decision

Use evidence-qualified dedicated activity guides as Kid Activity Lab's primary
editorial and SEO growth experiment. Keep broad hubs as concise choice and
routing surfaces, and keep activity cards as compact run-from-one-screen
utilities.

This is a format priority, not permission to publish one page for every idea
or keyword. Each guide still needs a distinct parent job, current search and
source evidence, one canonical owner, durable KAL utility, and no clean fit in
an existing page.

## What GSC Does Not Support

- There is only one long-form activity guide. Topic, query demand, age,
  internal links, page history, and content quality are confounded with page
  format.
- The ramp guide has existed since June and has received several improvements;
  newer pages have not had equal crawl and observation time.
- Public-safe snapshots omit complete query rows, so current query ownership
  and intent cannot be inferred from page rows alone.
- One click is useful but too sparse for a CTR or satisfaction conclusion.
- Search visibility does not prove that a parent understood the page or that a
  child enjoyed, learned from, or safely completed the activity.

The correct conclusion is therefore **strong directional support for a
guide-first experiment**, not proof that dedicated pages inherently outrank
hubs or cards.

## Supporting Demand Context

The July 28 Semrush refresh retained US monthly estimates of 210 for
`cardboard ramp` and 50 for `how to make a ramp with cardboard`. These are
dated `TOOL_ESTIMATE` values, not current GSC demand or KAL rankings. They do
show that the winning page pairs a concrete build job with a measurable query
family. A future guide must earn the same kind of query and task validation;
an appealing activity name alone is insufficient.

## Page Roles

### Dedicated activity guide

Own one concrete activity-running or problem-solving job. It may explain a
build, game, experiment, creative prompt, or exploration in enough depth that
a caregiver can judge fit, begin, recover from a common failure, and decide
what to vary next.

### Collection or chooser hub

Help a caregiver select among genuinely different jobs. Keep the number of
choices small, put the useful routes before long prose, and send depth to the
canonical guide. A hub should not repeat every guide in miniature.

### Activity card

Remain a compact execution surface. A card can support quick browsing or a
one-screen run and may route to a richer canonical guide. It should not compete
with that guide for the same search job.

## Candidate Gate

A dedicated guide is eligible only when all of these are true:

1. Current keyword and live SERP research identifies one concrete parent job
   rather than a wording variant.
2. The job is distinct from existing owners or an existing page cannot absorb
   it cleanly.
3. Current sources can support factual setup, rules, materials, supervision,
   and stop boundaries without invented firsthand evidence.
4. KAL can add maintainable utility such as a compact first start,
   substitutions, a chooser, troubleshooting, a comparison loop, or an
   original explanatory visual.
5. A source-derived caregiver persona task passes the pre-publication gate
   below on desktop and mobile.
6. The guide does not depend on unsupported medical, developmental,
   educational-outcome, allergy, toxicity, choking, or universal safety
   claims.

Do not create multiple pages for close keyword variants, individual ages, or
minor material substitutions. Improve the canonical owner instead.

## Parent-Task Simplicity Gate

Every guide must define one evidence-grounded caregiver task. The default task
is: decide whether this activity fits the current child and moment, then start
it without another broad search.

Before publication, verify at 1280x900 and 390x844 that the caregiver can find:

- what the activity is and why it may fit, without an engagement promise;
- the materials and realistic substitutions;
- the adult setup and first thing to say or do;
- a short kid-facing mission;
- readiness, supervision, stop, and cleanup boundaries;
- one rescue path when setup or interest falters;
- an easier or harder variation only when it earns its scan cost;
- the research-backed and not-family-tested boundary when applicable.

Every visible section must own one parent job. Compress, move, or remove a
section when it repeats an earlier answer, narrates SEO, delays the first
start, or adds more interpretation than decision value. Supporting detail and
sources belong after the runnable answer unless a trust-sensitive warning must
appear earlier.

A guide fails automatically when a critical instruction is missing, a
trust-sensitive claim is unsupported, the core task requires another broad
search, or the mobile page hides the start behind avoidable clutter.

## Next Experiment

Do not select or publish the next guide from this action. Run one separate
query/SERP decision pack across a small set of candidate activities already in
the maintained inventory. Choose at most one candidate using:

- distinct parent job and query family;
- realistic search opportunity rather than volume alone;
- source and maintenance feasibility;
- internal ownership and cannibalization;
- ability to add clear parent-first execution utility;
- fit with ages 3-6 and the current engagement lanes.

The research may reject every candidate. That is a valid result.

## Measurement Boundary

For each future guide, freeze the pre-release page/query baseline, crawl state,
persona task, page owner, and observation window. Observe indexing, crawl,
impressions, clicks, aligned queries when available, and the proxy task after
release. Do not claim that search movement proves caregiver usefulness or that
proxy review proves real family outcomes.

Reconsider the guide-first priority if several qualified guides receive fair
crawl windows without discovery, aligned queries favor existing hubs for the
same jobs, the guides add scan burden without parent decision value, or the
project cannot maintain the evidence standard.
